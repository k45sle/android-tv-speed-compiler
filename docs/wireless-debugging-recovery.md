# Wireless debugging and ADB

The Docker image includes ADB. You only need Docker on your computer. If you run the Python service directly, install Android platform-tools in that environment and make `adb` available on its PATH. The dashboard reports whether the service can find ADB; it does not download tools onto your computer.

Saved pairing keys let the service reconnect while Wireless debugging is enabled. Discovery can find a changed connection port. If discovery fails, enter the current connection IP:port under Manage TV details. If the TV turns debugging off, enable it on the TV before reconnecting. A disconnected server cannot send a command to turn it back on.

## Choose a connection method

| Method | Benefits | Limits |
| --- | --- | --- |
| Encrypted Wireless debugging | Android encrypts the ADB connection. Uses Android's built-in pairing screen. | The connection port can change. If the TV disables debugging, turn it back on; a manual connection address may be needed when discovery fails. |
| Traditional ADB on a fixed port | A predictable address is easier to reconnect to. A compatible TV companion can enable it after boot. | Traffic is unencrypted. Boot recovery requires a TV app or firmware support. The service's ADB key must still be authorized by the TV. |

Use a fixed port only on a trusted home network without port forwarding. Both methods give an authorized ADB client broad access to the TV. A public source repository does not mean the dashboard or ADB port should be publicly reachable.

## Optional fixed-port companion setup

The fixed TCP/IP wizard offers an unchecked-by-default checkbox to install and configure [adb-auto-enable](https://github.com/mouldybread/adb-auto-enable). Selecting it authorizes the wizard to install this third-party app, grant its declared `WRITE_SECURE_SETTINGS` permission, and change debugging settings. There is no separate approval prompt. The wizard downloads the official v0.3.5 release APK from [its release URL](https://github.com/mouldybread/adb-auto-enable/releases/download/v0.3.5/ADB-auto-enable-0.3.5.apk) and checks the pinned SHA-256 `454008f3dd2a90ffcd44fc14ac3baf183c6f29ec9b194c35bc21308485c8b13b`. This pins the downloaded bytes; it is not a claim of an independently signed release. The [v0.3.5 web server](https://github.com/mouldybread/adb-auto-enable/blob/v0.3.5/app/src/main/java/com/tpn/adbautoenable/WebServer.java) and [boot service](https://github.com/mouldybread/adb-auto-enable/blob/v0.3.5/app/src/main/java/com/tpn/adbautoenable/AdbConfigService.java) define the setup and reboot behavior described here. The companion's minimum SDK is 26, but that installation floor does not guarantee that a TV works with it. Android 11 or later and Wireless debugging are required for setup; upstream testing targets Android 14 and later.

After the service's ADB key is authorized, the wizard temporarily forwards the companion setup interface on TV port 9093 through the verified ADB connection. This forward does not limit the companion server to localhost: while **Enable Web Interface on Boot** is on, its unauthenticated HTTP setup interface is also exposed on the TV's LAN. The companion owns a separate ADB key, so setup asks the owner to complete one separate Android pairing-code prompt using the companion's pairing port on the TV. Enter that code only in the wizard's guided prompt. The service holds it only for the pairing attempt and never logs or stores it; the companion itself logs its one-time code on the TV. The setup page grants only the companion's declared `WRITE_SECURE_SETTINGS` permission. No Shizuku or root access is used or required for automatic or manual setup.

The companion defaults to port 5555. Choose a target from 1024 through 65535, except 9093, if another port is needed. The wizard configures the port, verifies the companion setup, disables **Enable Web Interface on Boot**, then switches ADB to the selected fixed endpoint and reconnects. It verifies the TV serial and build fingerprint before marking the TV ready and saving the fixed endpoint. It does not reboot the TV. If pairing, permission, connectivity, endpoint, identity, or companion setup fails, the wizard shows the failure and manual recovery steps; Finish stays unavailable while a requested automatic setup remains incomplete. If setup is canceled or abandoned before the interface is disabled, open the companion on the TV and turn **Enable Web Interface on Boot** off; do not leave its unauthenticated HTTP server exposed on the LAN. Retrying preserves existing pairing keys, saved mode, endpoint, and other device state.

An existing companion whose setup server is already disabled may need the owner to re-enable its setup interface on the TV before reconfiguration. OEM battery/background settings may also need attention on the TV. Boot-time reconnection has not been verified across TV firmware; do not assume that a successful setup proves reboot recovery. The companion may disable automatic expiration of ADB authorizations. Fixed-port traffic is unencrypted, so use it only on a trusted private network without port forwarding.

If the checkbox stays clear, the wizard follows the existing manual fixed TCP/IP flow. For adb-auto-enable, install it from its [official releases](https://github.com/mouldybread/adb-auto-enable/releases), open it on the TV, pair its ADB key using the TV's Wireless debugging pairing screen, choose and enable a fixed port, then enter that TV address and port in Speed Compiler. Turn **Enable Web Interface on Boot** off when setup is complete; it exposes an unauthenticated HTTP server on the TV's LAN while enabled. Approve the separate RSA prompt for Speed Compiler's own ADB key. Compatible firmware can also provide fixed TCP/IP without this app. Wireless debugging behavior is unchanged. In both methods, the companion has its own ADB key, which does not authorize Speed Compiler's key. The selected method is saved as operator metadata; it does not independently prove the live transport's encryption.

**Does setup need Shizuku?** No. Automatic and manual companion setup use Android pairing and ADB; neither requires Shizuku or root.
