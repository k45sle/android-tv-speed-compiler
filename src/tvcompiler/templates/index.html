Find your one-time token

In Docker Desktop, open Containers, select the android-tv-speed-compiler container, then open Exec (called Terminal in some versions). Run this command:

cat /data/instance/bootstrap.token

Copy the token printed by the command and paste it into One-time setup token below. This one-time step proves you control this installation; after setup, sign in with your password.

Using Docker Compose or a custom installation

From the correct repository and deployment, run this in a terminal on the Docker host:

docker compose exec android-tv-speed-compiler cat /data/instance/bootstrap.token

Run it from the same deployment directory with the same Compose file and project options used to start the service. For a Linux host deployment, include -f compose.linux-host.yaml and the same -p project name if one was used. For a source or custom installation, read the token from the configured instance directory’s bootstrap.token file. If your owner supplied TVCOMPILER_BOOTSTRAP_TOKEN, use that provisioned value; do not expose environment dumps or logs.

Add a TV

Name this TV

On the TV, open Settings → System → About and enable Developer options if needed. Then open Developer options → Wireless debugging and turn it on.

Wireless debugging status

Pair this TV

On the TV, choose Pair device with pairing code. Enter the pairing IP:port and short code shown in that popup. The service will find the connection when possible.

Connect to the TV

On the TV’s main Wireless debugging screen, enter its current IP address and connection port. “Already paired” means this service has the TV’s pairing keys saved.

Choose apps to watch

Select apps to save their current versions as baselines. No compile will be queued.

Review setup

Choose what Finish does

Monitoring checks for app updates on every watched TV. It does not force a foreground compile.

No initial compile is queued by default. Queued work waits for an idle TV and any maintenance window; awake, playback, unknown status, or a closed window can defer it. Queueing does not mean it starts or finishes now.

After a reboot, paired keys and watch settings remain saved. Keep this service and its Docker host running. If the connection changes, Wireless debugging is off, or discovery is blocked, turn it back on and save the current connection IP:port under Manage TV details. If keys were revoked or the verified TV identity changed, confirm the TV and pair it again.
